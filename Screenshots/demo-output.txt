3. Dockerfile lines that do not do what they are written to do
--------------------------------------------------------------
   | ARG APP_VERSION=1.4.2
   | FROM node:20-slim
   | RUN mkdir -p /app && cd /app
   | COPY package.json package-lock.json .
   | RUN npm ci
   | RUN echo "$APP_VERSION" > /version
   | ENV PORT=3000
   | CMD ["node", "server.js", "--port", "$PORT"]
   verdict: wrong (4 claims checked, 0 hold, 1 to check, 3 wrong)
   - [wrong] It does not hold that `RUN mkdir -p /app && cd /app` works as written: each `RUN` starts a new shell, so `cd` ends with it; `WORKDIR` is what lasts; write `WORKDIR /app` instead.
   - [check] `COPY package.json package-lock.json .` stops the classic builder: several sources need a destination ending in `/`; write `./` instead; BuildKit was not checked.
   - [wrong] It does not hold that `RUN echo "$APP_VERSION" > /version` works as written: an `ARG` declared before `FROM` is visible only to `FROM` lines until the stage declares it again; write `ARG APP_VERSION` instead.
   - [wrong] It does not hold that `CMD ["node", "server.js", "--port", "$PORT"]` works as written: the exec (JSON) form runs no shell, so `$` names are passed on as written; write `CMD ["sh", "-c", "node server.js --port $PORT"]` instead.

4. General statements about Dockerfile rules
--------------------------------------------
   answer: In a Dockerfile, `RUN cd /app` makes the following commands run in `/app`. `ARG` values are available at runtime. `WORKDIR /app` fails if the directory does not exist yet.
   verdict: wrong (3 claims checked, 0 hold, 3 wrong)
   - [wrong] It does not hold that `RUN cd` changes the directory for later instructions: each `RUN` starts a new shell, so `cd` ends with it; `WORKDIR` is what lasts; write `WORKDIR /app` instead.
   - [wrong] It does not hold that an `ARG` value is there when the container runs: an `ARG` exists only while the image builds; copy it into an `ENV` to keep it.
   - [wrong] It does not hold that `WORKDIR` needs the directory to exist already: `WORKDIR` creates the directory when it does not exist.
   rewrite: In a Dockerfile, `RUN cd /app` only lasts for that `RUN`. `ARG` values exist only during the build. `WORKDIR /app` creates the directory if it is missing.
   verdict: verified (2 claims checked, 2 hold)
   - [holds] It holds that `RUN cd` lasts only for its own `RUN`.
   - [holds] It holds that `WORKDIR` creates a missing directory.
